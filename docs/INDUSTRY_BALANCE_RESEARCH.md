# 炮塔数值与轻工业路线研究（2026-10-09）

## 结论与本轮边界

建议做**独立可玩的轻工业防线**，工业时代 2 仅作为可选材料/电力适配。先解决 Mod 敌我识别、攻击窗口、范围预览，再上材料与能源闭环；不要先把全部炮塔伤害统一乘一个系数，也不要一次复制完整终末地工业。

本轮只有静态分析、建议、资源提取和离线算例。没有改 `Mod/`、`tools/towers.json`、模型项目、已安装游戏、现有世界或发布包。新数值在 `docs/tower-balance-candidate.json`，**游戏不会读取这个文件**。截图内聊天是反馈材料，不是对本轮的额外执行指令。

## 1. 实际查了什么

- 对用户 Mods 目录 36 个 scmod 记录原包 SHA-256、目录和相关程序集/配置；读取标准 ZIP 及 API 自带的两种封装。原包只读，不运行第三方程序集。
- 工业时代 2 `1.0.0.2`：配方、自动机枪/激光、电网、基础/高级电路；物流附属 `1.0.0.1`：带组拓扑、库存运输、供电检测和可视化分离。
- 尸鬼 `2.0`、恶灵传说 `2.1`：生物模板及受伤/行为代码；CS 武器 `1.5.0`：敌兵/人质模板；BF2042 `0.4.6`：载具模板。玲兰科技检查到载具模板，但不把它当主要敌人基准。
- 杂交工艺/深海迷航：外层配置与代码可读，生物资源另在 `Assets.pkg` / `assets.index + chunk` 内，本轮没有进一步解包；不编造其生命值。杂交繁育代码存在遗传与成长倍率，固定模板也不能代表所有后代。
- 对用户实际 `Survivalcraft.dll` 的 `Attackment`、`ProjectileAttackment`、`SubsystemSpawn` 做静态反编译，不以另一个 API 开发版替代。
- 提取终末地工业/物流/攻击范围及依赖，导出原始网格、贴图、材质、场景结构和配置。未做方块模型改造，也未声称 Unity 场景在 SC 中可直接播放。

机器可读证据：`local/balance-research/mod-audit.json`、`entity-stats.json`、`paper-comparison.json`。实体清单共 82 条有显式抗性字段的模板，包含自己的旧包、载具、非敌对单位；**不是“82 种敌人”，不是最终合并后的运行时数据库**。模板继承、难度、护甲、脚本阶段及模组加载顺序仍会改变结果。

## 2. 比狼更重要的本地参照

这里的“抗性”主要是 `AttackResilience`。无护甲/倍率时，满血 1.0 的生物可近似把它理解为所需攻击力总额，但它不等于所有 Mod 的最终有效血量。实际 API 先算衣物护甲、`ComponentFactors.ResilienceFactor`，再除以抗性，之后还会经过 Mod 伤害钩子。

### 限伤必须进入计算

恶灵 `SirenHeadLoader.CalculateCreatureInjuryAmount` 直接限制每次 `Injury.Amount`，对炮塔来源也生效。尸鬼 Dark/熊限制单次最多 50，并在一秒窗口累计到 50 后把后续伤害压到极低值；窗口边界和一次跨线命中会影响精确结果，不能写成理想连续 DPS 上限。Corpsifice 类似，按阶段使用 100/200 的一秒预算。

尸鬼的难度倍率有“攻击者是玩家”的条件，炮塔是独立实体，不应直接把玩家伤害难度倍率套上去。全体炮塔都通过 `ProjectileAttackment` 结算，当前“物理/火/酸/光”首先是表现与附加效果，不等于已经接入对方 Mod 的元素抗性体系。

因此：**慢射炮单次必须更有分量，但不能承诺慢射炮对所有 Boss 更强**。不建议取消 Boss 限伤，也不建议把一发炮弹暗拆成几十次伤害来钻规则空子。专长、范围、首发打击、控制与持续输出应各有用途。

## 3. 现有实现中，比改数字更先处理的点

1. **敌我识别。** `MDCombat.IsEnemy` 只认陆地/水中捕食者或原版追击目标为玩家。尸鬼大量 `Bird`、CS `LandOther` 可能在未追击/自定义 AI 时漏选；载具甚至不是 `ComponentCreature`。建议未来显式阵营适配：玩家/己方/中立排除 → 已知敌对模板/组件 → 有明确敌意的回退。不能把所有 Bird/LandOther 都改成敌人，人质、家畜、飞鸟仍需保护。
2. **墙与范围规则。** `AreaTick`、`Pulse`、`ZoneTick` 没有完整的地形遮挡检查；高伤后穿墙喷火/毒雾会更严重。直射必须视线检查，迫击炮可允许间接火力但弹道仍受方块阻挡。圆范围/矩形范围、最小射程和开火瞬间重验应共用几何判定，避免预览和实打不一致。现有方向塔先做圆形距离裁剪再做矩形，矩形远角会被切掉。
3. **运动目标。** 普通弹 40–45 格/秒、榴弹 14–26，当前瞄准目标当前位置，不做速度提前量。射程加倍但弹速不改，快速 Mod 怪会更难打中。候选弹速随射程给出，但仍需先验证提前量、炮口安全、弹道可达、俯仰及寿命。
4. **持续攻击与控制。** 毒区可以重复叠加；多声波塔错峰可压成长期控制；`power` 对光束/喷射代表整次攻击而非每帧。不要用“单发/间隔”冒充毒区、弹射和分段光束的总 DPS。建议同类区域取最强、不无限叠，Boss 遵守其韧性，硬控有恢复期。
5. **医疗比例过强。** 当前每 5 秒恢复 20% 对玩家和 2600 抗性大炮都一样：后者单次 520 等效修复量。建议变为每 3 秒 4%，并设绝对修复上限（例如 25，取两者较小者），生物治疗与机械维修后续分开消耗品。
6. **排序与距离。** `threatFirst` 对 Damage 单位只比较归一化 Hitpoints，对 Health 单位比较 Health×抗性，尺度不一致。未来适配载具时要修正；大怪应考虑包围盒/可命中部位，不只拿中心点距离。
7. **怪物能否反击，以及普通命中的隐含控制。** 塔是独立 `ComponentDamage` 实体，某些只寻找 `ComponentCreature` 的 Mod AI 不一定会攻击塔；本轮没有运行验证，不能以“塔有650血”推断会遭受完整围攻。用户 API 的 `ProjectileAttackment` 默认还有0.2秒眩晕和冲量2，快射/多塔也可能形成持续硬直，不能只限制声波塔而漏掉普通命中。后续需分别测塔仇恨、拆墙/远程攻击和普通弹硬直。

## 4. SC 射程建议的依据

工业自动机枪 `ComponentAutoGun`：约 0.14 秒一次、消耗实体弹药，弹速 260；传入索敌半径 64，但目标可见性检查和开火安全射线使用 50。因此不能简单宣称“有效射程 64”。工业激光也使用 64/50 的查询结构，伤害与输入电功率相关；不是免费固定伤害。

用户 API 的 `SubsystemSpawn` 默认生成半径 48、收回半径 60，均与玩家/摄像机附近活动有关，不是以每座塔为中心维持全图活跃。Mods 可以覆盖这些值。视距大也不代表远处存在可模拟的敌人。

建议普通直射 **28–36 格**，重能量 **32–40 格**，狙击/迫击炮 **48–56 格**，近防 **9–10 格**。56 是待测上界，不是保证随时有效；超过 60–64 不作为第一版目标。每次扫描先空间查询再筛选候选，避免每塔扫描所有实体；只有玩家手持/选中塔时显示范围。

以速度 10 的警笛头直线接近为例：15 格约 1.5 秒、36 格约 3.6 秒，尚未扣除安全距离、转向和弹道。移动期间瞄准/装填/转台不一定全部串行，实际要按时间线测试。仅把一发加到几百仍不足以解决短射程与限伤。

### 纸面算例——明确不是实测

`python tools/analyze_tower_balance.py` 产生精确的离散命中序列与限伤算例。以下均假定立即首发、持续命中、没有移动/护甲/转向/地形/弹道延迟：

- 60 等效血量普通敌人：候选基础铳械塔需 3 发，首发至击杀约 1.2 秒。不是“DPS 40 所以固定1.5秒”，首发时刻必须说明。
- 无限伤的 1600 等效血量：候选暴雨约 9.6 秒，哨戒约 13.5 秒。哨戒用更长射程与高首发换持续 DPS，不要求同价全维度胜出。
- **真正芬里尔（80/次上限）**：候选暴雨约 10 秒；候选哨戒约 85.5 秒。480 大炮只能结算 80，不能拿无限伤结果冒充芬里尔击杀时间。
- **警笛头（12.288/次）**：候选暴雨约 33.2 秒；候选哨戒约 373.5 秒。说明这类 Boss 的设计就是考验持续命中与防线维持，不是靠一座大炮秒杀。
- 这不是让所有炮塔都改成快射：狙击仍服务无此限伤的高价值目标，迫击炮服务群体。若希望慢射炮也有 Boss 特效，应单独协商兼容规则，不能偷偷绕过限制。

推荐三档**配置目标**而非自动读血量动态抬伤：原版轻量档可降低战斗伤害并缩小射程；本表 Mod 标准档；高压 Boss 档仅在确认玩家常玩哪些敌人后调持续输出/供电与数量。不要给未知 Mod 一个全局 ×10。

## 6. 材料与能源：小而完整的路线

### 工业 Mod 值得借鉴的部分

实际 `.ier` 配方不是只塞更多铁块：钢、板/杆/齿轮 → 机壳/活塞 → 发电/电机 → 基础电路/高级电路 → 雷达/电容/炮塔。基础电路用铜线、二极管、锗、存储器、锡；高级电路组合原版真值表、计数器、存储器、时钟与工业元件。自动机枪需要高级机壳、雷达、运动探测器、电容、铜线和枪管，且持续消耗弹药与电力。

借鉴它的“中间件有复用价值、装备有运行成本”，不要机械照搬其全套配方和复杂度。物流附属已有带组注册表、脏拓扑重建、库存运输模拟和独立渲染；适合借鉴架构，不能把每件货做成带物理的独立生物。

### 建议分三段，但第一段就能玩

| 阶段 | 核心材料/设备 | 解锁与体验 |
|---|---|---|
| T1 基础机械 | 原版铁/铜/煤/锗 → 钢板、铜线、基础电路、机壳；简易发电/电池座 | 基础铳械、榴弹、激流；可手动补给，不要求先造整条流水线 |
| T2 加工与储能 | 精炼炉、配件/压制、装配；电容、转台伺服、强化机壳 | 扩装、能量/辅助塔，供电桩与储能、短传送带/箱子；维修材料通用 |
| T3 自动化防线 | 高级控制板、复合装甲、功率模块、制导/光学件 | 暴雨、哨戒、迫击炮、高能塔，分流/汇流与生产线，电网有容量规划 |

第一版控制在约 8–12 种共用中间件，别让每座塔各用一堆专属材料。材料应该同时能用于炮塔、发电、后续机甲，旧塔作为升级输入或能回收主要部件；损毁只返一部分，避免拆装刷材料。

可用作讨论起点的**组合成本**（不是可安装配方）：T1 塔=机壳1+钢板8+铜线4+基础板1+动力件1；T2=对应T1核心/机壳+强化板8+高级板2+电容2+伺服2；T3=对应T2核心+复合板12+高级板4+功率模块2+专用火控件1。升级应继承已有投入，不按数据编号直接替换而丢失状态。资源采集耗时、产量和批量配方尚未做实玩验证，以上数量不定稿。

### 供电原则

推荐：发电/电池座 → 中继器（输电）→ 供电桩（局部覆盖）→ 塔内电容 → 开火。原版 SC 电信号只做开关，不把“有电压”当无限能源。

终末地原表确有 `attackCost`、`energyMax`、`energyChargeCount/energyChargeMillSec`；多数塔储能2400、充能100/1000ms，但枪塔1/2/3每发耗能是10/40/10，不能据此宣称能耗必然随等级递增。原作供电桩 `rangeExtend=(5,5,5)`、连接长度字段30；中继器连接长度80且默认不提供扩散供电。**这些是字段含义和扩展量，不直接等于 SC 球形半径**。

电池有两套不同数据：`FactoryBatteryItemTable.BatteryEnergy` 为 8800/20800/54000/72000/152000；`FactoryFuelItemTable` 又有燃料进度及发电功率220/420/1100/1600/3200。不要把 `fuelEnergy=240000` 或热能池基础150误当所有电池可直接通用的焦耳/瓦时。

SC 候选：定义独立 DU（储能）/DU每秒（功率），明确换算；初期发电机120 DU/s、桩半径8格（需另验三维覆盖）、中继跨度32格、T1/T2/T3电池12000/48000/144000 DU。基础铳械10 DU/发≈16.7 DU/s；暴雨32/发=80 DU/s；哨戒160/发≈35.6 DU/s；迫击炮400/发≈57.1 DU/s，高能束600/次=120 DU/s。加待机耗能和其他机器后，一台120发电机不能无限带高级塔阵。

这组能源量级仅用于预算讨论：基础电池供基础枪约720秒、供暴雨约150秒（忽略待机损耗），从而赋予高级电池与补给线意义。缺电显示“储能不足”，保留索敌但不白放特效/不扣半份弹药；断网先用内置缓冲，存档保存能量、库存、网络拓扑版本。离线区不偷偷模拟无限刷资源。
